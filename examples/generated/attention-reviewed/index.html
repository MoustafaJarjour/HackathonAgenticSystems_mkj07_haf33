Scaled Dot-Product Attention with Tiny Q, K, V

UnderstandExploreCheck the source

The concept

Scaled dot-product attention turns a query into a weighted average of value vectors. Each query is compared with every key by a dot product; the scores are divided by √d_k (d_k = number of key/query feature columns) and passed through a row-wise softmax to form nonnegative weights that sum to one. The output row is the weighted sum of the value rows. Editing the tiny Q, K, V matrices lets you watch scores, weights, and outputs change together.

Why it matters

Attention is the core operation of the Transformer: it lets each position gather information from all other positions in proportion to query-key compatibility. Understanding the score → scale → softmax → weighted-sum pipeline explains why the 1/√d_k factor exists and why attention weights are always a probability distribution over positions.

Symbols and terms

query
A vector representing what one position is looking for; each row of Q is one query.
key
A vector representing what one position offers for matching; each row of K is one key.
value
The vector that gets averaged; each row of V is the value at one key position.
d_k
The number of feature columns shared by queries and keys; read here as ncols(K).
softmax
Row-wise normalization that turns scores into nonnegative weights summing to 1.
attention weights
The matrix of attention weights, one row per query, one column per key.

How the mechanism works

  1. Score each query against every key

    Attention compares a query with every key using a dot product. The dot product reflects both alignment and magnitude; it is the query-key compatibility score used here. The source describes the output as 'a weighted sum of the values, where the weight assigned to each value is computed by a compatibility function of the query with the corresponding key.'

    Source-supported relationship Evidence: weighted_sum

  2. Scale by √d_k, then softmax each row

    The source scales dot products by 1/sqrt(d_k) before softmax: 'We compute the dot products of the query with all keys, divide each by sqrt(d_k), and apply a softmax function to obtain the weights on the values.' Here d_k is read from the actual feature columns of K, and the fixed example has d_k=2.

    Source-supported relationship Evidence: scaled_dot_product, dk_dimension

  3. Average the values with those weights

    The softmaxed weights multiply the value matrix: output row i is the weighted average of the value rows. Because softmax rows sum to 1, the output is a convex combination of values. If all keys are identical, every score in a row is equal and the weights are uniform; if a query is the zero vector, all its scores are 0 and its weights are also uniform.

    Source-supported relationship Evidence: softmax_rows, weighted_sum

Teaching simplification

Try these explorations

  1. Change: Set both rows of K to the same vector, e.g. K = [[1,0],[1,0]], and leave Q = [[1,0],[0,1]].

    Observe: Every scaled score in a row becomes equal, so each attention weight is 0.5 and each output row is the average of the two value rows.

    Why: Identical keys have identical compatibility with any query, so softmax over equal scores is uniform. This is an analytically exact edge case: no decimal guessing is needed.

  2. Change: Set the first row of Q to [0,0] (a zero query) while keeping K = [[1,0],[0,1]] and V = [[1,0],[0,1]].

    Observe: The first row of scaled scores is [0,0], so its weights are [0.5,0.5] and its output row is [0.5,0.5], the mean of the value rows.

    Why: A zero query has zero dot product with every key, so all scores are 0 and softmax gives uniform weights. This shows that 'no preference' still produces a definite weighted average.

  3. Change: Keep the fixed 2x2 shapes but edit existing Q, K, and V values: for example, scale the first query row of Q to [2,0] while leaving K = [[1,0],[0,1]] and V = [[1,0],[0,1]].

    Observe: The first row of raw and scaled scores changes, so the first row of attention weights becomes nonuniform; the weighted output row changes accordingly. The second query row and its output are unchanged.

    Why: Changing query or key magnitudes changes compatibility scores and therefore the softmax distribution, while the weighted output remains a convex combination of the same value rows. This lesson uses fixed tiny matrices, so d_k and the matrix shapes cannot be resized here; dimension scaling is derived from the actual feature columns of the supplied K.

Assumptions and limitations

  • The demo does not train or learn Q, K, V; it only evaluates the attention formula on hand-supplied matrices.
  • The matrices are fixed tiny 2x2 teaching inputs; their shapes and d_k cannot be resized in this lesson.
  • Even with two keys, large score differences can produce strongly concentrated weights. This tiny example illustrates the attention formula without modeling a trained attention layer.
  • No masking, multi-head splitting, or positional encoding is modeled, even though the full Transformer uses them.
  • The displayed row sums are a numerical check, not a claim about the source text.

Our teaching simplifications

  • Q, K, and V are supplied teaching inputs, not learned linear projections; the real model derives them from embeddings with learned weight matrices.
  • The demo uses fixed 2x2 matrices with two queries and two keys, far smaller than real attention layers; their shapes and d_k cannot be resized in this lesson.
  • The raw (unscaled) score matrix is shown for comparison but is not itself part of equation (1).
  • Row sums are displayed as a numerical sanity check that softmax rows total 1.
