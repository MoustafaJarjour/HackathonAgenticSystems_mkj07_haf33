From a relationship to a working model

Scaled Dot-Product Attention with Editable 2×2 Q, K, and V

UnderstandExploreCheck the source

The concept

Queries and keys are compared by dot products; dividing those scores by sqrt(d_k) (the actual number of query/key feature columns) and applying a row-wise softmax turns the scores into weights that sum to one, and the output is the weighted sum of the value rows. With tiny editable matrices you can see every intermediate quantity: raw scores Q·Kᵀ, scaled scores, softmax weights, and the weighted output.

Why it matters

Scaled dot-product attention is the core mixing operation of the Transformer: it decides, for each query, how much of each value to read. In this lesson d_k is fixed at 2, and the scaling visibly reduces the spread of the demonstrated scores, which controls how concentrated the softmax weights become. Understanding the raw scores, the scaling, and the resulting weights is the prerequisite for understanding multi-head attention and the rest of the architecture.

How the mechanism works

  1. Scores compare each query with each key

    Pack the queries as rows of Q and the keys as rows of K. The raw score for query row i against key row j is the dot product of those two rows, i.e. entry (i,j) of Q·Kᵀ. A large positive score means the query and key have a large dot product: this depends on both their directions and their magnitudes, so it is not the same as cosine similarity. For example, a long vector can score highly against a moderately aligned key, while a short vector pointing in the same direction scores lower.

    Source-supported relationship Evidence: dot_products, packed_matrices

  2. Divide by sqrt(d_k), then softmax each row

    The raw scores are divided by sqrt(d_k), where d_k is the number of feature columns of Q and K (here 2). Then softmax is applied to each row of the scaled score matrix, so each query's weights are nonnegative and sum to 1. In this fixed d_k = 2 demonstration, the division shrinks the score spread and therefore makes the softmax weights less concentrated.

    Source-supported relationship Evidence: divide_sqrt, softmax_rows, dimension_dk

  3. Output is the weighted sum of values

    The output row for query i is the weighted average of the rows of V using that query's softmax weights. If one weight is near 1, the output copies that value row; if the weights are equal, the output is the plain average of the value rows.

    Source-supported relationship Evidence: weighted_sum

Try these explorations

  1. Change: With Q = [[1,0],[0,1]], K = [[1,0],[0,1]], V = [[1,0],[0,1]], flip the scaled toggle between 1 and 0.

    Observe: At toggle 1 the scaled scores are 1/sqrt(2) ≈ 0.7071 on the diagonal and 0 off-diagonal. The first weight row is about [0.6698, 0.3302] and the second weight row is about [0.3302, 0.6698], so each row is more concentrated on its matching key. At toggle 0 the scores are 1 and 0, giving first row about [0.7311, 0.2689] and second row about [0.2689, 0.7311], so the weights become more concentrated on the diagonal and the output moves closer to the corresponding value row.

    Why: Dividing by sqrt(d_k) shrinks the score spread, which makes the softmax weights less concentrated. Removing the scaling (the teaching construction) leaves larger score differences and therefore sharper weights; this is the effect the scaling factor is meant to control.

  2. Change: Set Q = [[0,0],[0,0]] (zero queries) and leave K, V, and the toggle at their defaults.

    Observe: Every raw score is 0, so every scaled score is 0 and each weight row is exactly [0.5, 0.5]; the output is the average of the value rows, [[0.5,0.5],[0.5,0.5]].

    Why: Zero queries give zero dot products with every key, so softmax over equal scores returns exactly uniform weights. This is an analytically exact edge case, not a numerical approximation.

  3. Change: Set K = [[1,0],[1,0]] (identical keys) and keep Q = [[1,0],[0,1]], V = [[1,0],[0,1]], toggle = 1.

    Observe: Both columns of the score matrix are equal, so both columns of the weight matrix are equal: each row is [0.5, 0.5], and the output is again the average of the value rows.

    Why: Identical key rows make every query's dot product with key 1 equal to its dot product with key 2, so softmax cannot distinguish them and splits the weight equally. This is another exactly derivable case.

Assumptions and limitations

  • Q, K, and V are supplied teaching inputs, not learned linear projections; the lesson does not show how they are produced.
  • The 2×2 matrices are a toy demonstration and do not reproduce any experimental result from the paper.
  • The unscaled comparison is a teaching construction added for contrast; the paper's attention always divides by sqrt(d_k).
  • The lesson does not cover multi-head attention, masking, positional encodings, or training.
  • Small matrix size does not by itself prevent softmax saturation: with large enough score differences, the weights can still become arbitrarily concentrated.

Our teaching simplifications

  • Q, K, and V are treated as directly editable 2×2 teaching inputs rather than outputs of learned linear projections.
  • The 0/1 toggle that removes the 1/sqrt(d_k) division is a teaching construction for comparison; the paper always uses the scaled form.
  • The 2×2 size and the specific default matrices are chosen for hand-checkable arithmetic and are not from the paper.
  • The claim that removing the scaling concentrates the weights is illustrated on a toy case; it is not an experimental result from the paper.
